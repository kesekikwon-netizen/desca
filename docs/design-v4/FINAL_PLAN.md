> 이 문서 전체가 당신(개발 에이전트)에게 주는 작업 지시다. **끝까지 읽은 뒤 시작하라.**
> 사용자는 비개발자다. 모든 질문·보고는 **한국어**로, 전문용어는 처음 나올 때 한 줄로 풀어 쓴다.
> 이 앱은 사용자가 오래 쓸 도구다. 속도보다 **정확성 · 되돌릴 수 있음 · 실행해서 확인한 증거**가 먼저다.

> 이 문서는 `design-v2\DEV_PROMPT.md`(2차 지시서)를 **대신한다.** 2차 지시서는 기록으로만 남는다.

## 0. 목표

C++/Qt 데스크톱 앱 **Kerf**(발굴 단면뷰어)에 디자인 개선 1차 → 2차 → 3차를 합친 **v4 최종안**을 구현한다.

1. **같은 일을 하는 UI 자리 26곳을 하나로 정리한다**(2차 감사표).
2. **평면도·단면도를 만드는 흐름에서 결과를 믿기 어렵게 만드는 8가지를 고친다**(2차 흐름 문제).
3. **2차가 새로 흩어 놓은 안내를 한 덩어리로 묶고, 목록을 하나로, 저장을 한 번에 한다**(3차).
4. 중복이 다시 생기지 않게 **`--ui-audit` 확인**을 만든다.

기능은 빼지 않는다. 단추의 **자리**를 정리하고, 화면에 **안내**를 더하고, **여러 장 저장**을 새로 넣는다.
단면 계산·도면 출력의 결과값은 바꾸지 않는다. 단, 0단계에서 계산 오류가 확인되면 사용자 승인 후에만 고친다.

**결정은 모두 닫혔다(§1).** 시작 전에 사용자에게 물을 것은 없다. 작업 중에 이 문서와 코드·기록이 어긋나면 그때만 묻는다.

## 4. 절대 규칙

**제품 규칙** (출처: `docs/intent/`, 인수인계 문서 — 바꾸지 않는다)
- 작업 화면은 **왼쪽 평면(3D) · 오른쪽 단면** 배치.
- **조판은 메인 영역의 탭.** 별도 OS 창이나 전체화면 창으로 띄우지 않는다.
- 평면도와 단면도는 **같은 바깥 도곽**(테두리 · 표제란 · 축척 막대 · 진북 나침반 · 범례 자리)이고 그림 칸만 다르다.
- **평면도 그림 칸은 정사영상만.** 단면선 없음, 진북 나침반 필수.
- 단면도 그림 칸은 입면 영상 · 레벨선 · 단면선. 그리는 순서 **레벨선 → 영상 → 단면선**.
- 축척은 `QSpinBox` 10단위, 화살표로 10씩, 상한 없음, **도면마다 따로 저장**.
- 바깥 좌표·표고 숫자는 그림 칸 바깥에서만. 글자에 가로·세로 배율을 따로 먹이지 않는다(`QPainter::scale(1, z)` 금지).
- 단면선 색 순수 빨강 `#FF0000`. 레벨선 10 cm, 숫자 50 cm.
- 좌표는 메시 로컬 + SRSOrigin. 높이는 파일 값 그대로, **지오이드 재적용 없음.** 자북·GPS를 지어 넣지 않는다. 나침반 글자는 「진북」만.
- 입면 배경(뒤 깊이 0–5 m, 기본 3 m)은 토층 그리기에 필요하다. **없애거나 기본값을 끄지 않는다.**
- 왼쪽 3D 조작(왼쪽 끌기 = 밀기, 휠 = 확대, 오른쪽/가운데 끌기 = 기울기, T·N = 제자리)은 그대로.
- 「조용한 도판」: 종이 `#FAF9F5` · 먹 `#141413`, **흙색 `#B5573A`는 한 화면에 주 단추 하나**, 이름은 명조 · 잰 값은 모노 · 나머지 고딕. 토큰은 `app/theme.hpp`. 새 색·크기를 직접 쓰지 않는다.

| 알림 | 작업 화면은 단면 정보 줄 한 칸, 도면은 「도면 점검」 한 덩어리. **그 밖에 새 띠·배너를 만들지 않는다** |

키·오른쪽 클릭 메뉴는 지름길이라 겹쳐도 된다. 눈에 보이는 단추는 한 번만.

**작업 규칙**
- `MainWindow`에는 `Q_OBJECT`가 없다(moc 없이 빌드 — MinGW 교차 빌드 전제). 연결은 람다, `qobject_cast` 대신 `static_cast`. 새 클래스에도 moc가 필요한 기능을 쓰지 않는다.
- C++17 유지. 핵심 계산은 Qt 없이 `core/`에 두고, 계산을 바꾸거나 더하면 `tests/`에 **먼저 실패하는 시험**을 넣는다.
- `third_party/`, 빌드 출력, 생성 파일은 고치지 않는다. 파일 전체 재포맷 금지(바꾼 줄만).
- **커밋 · 푸시 · 배포는 사용자가 말할 때만.** 작업 시작 때 「단계마다 이 브랜치에 커밋해도 될까요?」를 한 번 묻는다. 허락받으면 단계마다 커밋(메시지 한국어, 무엇을 · 왜). force push, 히스토리 재작성, main 직접 수정 금지.
- **한 번에 한 목표.** 고친 뒤 실행해서 화면을 보고, 본 것만 말한다. 캡처나 기록으로 판정한다.
- 같은 문제로 두 번 실패하면 멈추고, 시도한 것 · 알게 된 것 · 선택지를 보고한다. 시험을 끄거나 경고를 숨겨서 통과시키지 않는다.
- 자동 실행은 항상 `--settings C:\dev\tmp\kerf-check`처럼 격리한다.

### 단계 14 · 여러 장 저장 (D6 · D7 · D10 · v3)

- **파일 이름 함수는 `core/`에 Qt 없이:** `(모델 이름, 도면 이름, 축척 분모) → 파일 이름`. 규칙: `모델_도면_1-분모.svg`, 도면 이름의 `–`(en dash)는 `-`로, `′`는 그대로, Windows 금지 글자 `\ / : * ? " < > |`는 `_`로, 앞뒤 공백·점 제거. 같은 이름이 있으면 `_2`, `_3`… 를 붙이는 함수도 함께. **시험 먼저**(한글 · ′ · 금지 글자 · 겹침).
- 주 단추 글: 고른 0장 = 비활성 「고른 도면 없음」, 1장 = 「SVG 저장」(형식에 따라 「PDF 저장」 등), n장 = 「n장 SVG 저장」. n ≥ 2이면 형식은 SVG만 켜지고 나머지는 툴팁 「여러 장 저장은 지금 SVG만」과 함께 꺼진다. 흙색 단추는 이것 하나.
- 누르면: 폴더를 한 번 묻는다(기본 = 이 모델에서 마지막으로 저장한 폴더) → 같은 이름이 있으면 한 번에 묻는 창(`States` 5: 기본 단추 「이름 뒤에 _2」, 「취소」, 글자 단추 「덮어쓰기」) → 장마다 **기존 한 장 저장 함수를 그 장의 저장된 축척 · 용지로** 호출한다(새 그리기 코드 금지).
- 진행(`States` 2): 판 아래 한 줄 `3 / 4` 막대 + 장마다 「✓ 저장 22:14 / 저장 중… / 기다림」 + 「멈추기」(이미 저장한 파일은 지우지 않음). 진행 중 주 단추는 「저장 중…」로 잠김. UI가 멈추지 않게 한다(지금 조판 저장이 어떻게 도는지 먼저 읽고, 같은 방식으로).
- 끝(`States` 3): 판 아래 결과 줄 「✓ n장 저장함 · 폴더 경로」 + 「폴더 열기」. 다른 도면을 고르거나 설정을 바꾸면 사라짐. 목록 줄의 「저장 시각」이 바뀐다.
- 일부 실패(`States` 4): 「● n장 저장 · m장 못 함」 + 장 이름과 사람이 고칠 수 있는 이유(경로 · 권한 · 공간) + 「다른 폴더…」 · 「그 장만 다시」. 성공한 파일은 그대로.
- 시험용 옵션 `--sheet-batch DIR`: 목록의 모든 도면을 DIR에 저장하고 `sheet-batch saved=n failed=m names=…`를 기록한다(같은 이름 창은 자동으로 `_2`).
- **완료 조건:** 새 core 시험 통과 · `--sheet-batch`로 평면도 + 단면 3장(`--extra-line`) 저장, 파일 이름 · 장마다 축척이 맞음 · 같은 폴더에 두 번 돌리면 `_2` 파일이 생기고 원본이 남음 · 읽기 전용 폴더로 실패 상태 캡처.

## 9. 추가 요청 (2026-10-09) — 잘린 돌 빗금 · 평면 유물 윤곽

> 사용자 요청: 「유구도면에서 돌 같은 것이 단면에 잘리면 빗금으로 단면 처리를 하는데 그리기가 어렵다. 평면의 유물 · 돌 · 기와도 힘들다. 수동으로 확인해 그리는 게 좋겠지?」
> 원칙: **사람이 확인한 것만 도면에 들어간다.** 앱은 후보 찾기 · 경계 붙이기 · 빗금 칠하기를 맡는다. 자동으로 찾은 것을 묻지 않고 도면에 넣지 않는다.
> v4 핵심 단계(−2 … 17)가 끝난 뒤에 한다. 아래 「정할 것」 두 가지는 시작 전에 사용자에게 묻는다.

### 왜 이 방식인가
- **메시는 겉면뿐이다.** 3MX · OBJ 실사 메시는 속이 빈 껍데기라, 단면이 돌을 지나도 앱은 「돌의 윗면이 잘린 선」(빨강)만 정확히 안다. 흙 속에 묻힌 돌의 아래쪽 경계는 메시에 없으므로 **사람이 판단해야 한다.**
- **빗금 자체는 기계가 더 정확하다.** 닫힌 영역만 정해지면 빗금 선은 축척 · 간격 · 각도에 맞춰 정확히 자를 수 있다. 일러스트레이터에서 손으로 하는 가장 힘든 일이 이것이다.
- **평면의 돌 · 기와는 색보다 「높이」가 잘 보인다.** 정사영상은 그림자 · 흙색 때문에 경계가 흐리지만, 메시 높이에서 주변 평균 높이를 뺀 **국소 기복**(조금 솟은 정도)을 보면 돌 · 기와 · 유물의 윤곽이 또렷해진다. 그래도 오탐이 있으므로 후보로만 보여 준다.

### 단계 A1 · 단면 빗금 — 사람이 정하고 기계가 칠함
- **도구 「잘린 돌 칠하기」(키 H)** — 홈 리본 「단면」 묶음(손에 드는 도구). 아이콘은 빗금 사각형(Icons 화판에 더한다).
- 그리는 법(단면 화면):
  1. 빨간 잘린 선 위에서 시작점과 끝점을 클릭 → **윗경계는 잘린 선을 그대로 따라 자동으로 붙는다**(메시가 정확히 아는 부분).
  2. 흙 속 아래쪽 경계만 몇 번 클릭(입면 영상 · 토층면 사진을 보며). Enter로 닫으면 바로 빗금 미리보기.
  3. 종류: 돌 · 기와 · 유물 · 기타(오른쪽 클릭으로 바꿈). 지우기 Del, 되돌리기 가능.
- **빗금 생성은 `core/`에 Qt 없이:** `hatchPolygon(다각형, 각도, 간격) → 선분들`(짝-홀 규칙, 구멍 있는 다각형 포함). 시험 먼저: 정사각형 · 오목 다각형 · 구멍 · 각도 0/45/90 · 아주 얇은 영역.
- **영역 닫기도 `core/`:** `closeCutRegion(잘린 선, s0, s1, 아래 점들) → 다각형`. 시험: 잘린 선이 끊긴(빈 구간) 곳을 지나면 실패로 알림.
- 저장: 모델별 · 단면별 영역 목록(단면 좌표 s · z). **단면선을 옮기거나 방향을 바꾸면** 그 단면의 영역은 「다시 확인」 표시(흐린 빗금 + ▲) — 저절로 맞추지 않는다.
- 도면 · 화면 그리는 순서: 레벨선 → 영상 → **빗금** → 단면선(빨강은 맨 위 그대로).
- 출력: SVG · DXF에 따로 층 `SECTION_CUT_FILL`(빗금 선) · `SECTION_CUT_OUTLINE`(영역 테)로 — 일러스트에서 굵기 · 간격을 다시 바꿀 수 있게. 빗금 간격 · 각도 · 선 굵기는 **종이 위 mm**로 정한다(기본 1.0 mm · 45° · 0.13 mm, 축척이 바뀌어도 종이 위 간격은 같음). 조판 설정 판에 「빗금」 줄 하나.
- 도면 점검에 항목 하나: 「빗금 — 다시 확인할 영역 n곳」(단면선이 바뀐 영역이 있을 때만 ▲).
- **완료 조건:** core 시험 통과 · 합성 모델 시험 선에서 영역 2개를 그려 화면 · SVG · DXF 캡처, 층 이름 확인 · 축척 1:20과 1:40에서 종이 위 빗금 간격이 같음.

### 단계 A2 · 단면 빗금 후보(반자동)
- 도구를 든 동안 도구 줄에 「후보 보기」 단추. 잘린 선 바로 아래 입면 영상에서 **색이 주변 흙과 다른 덩어리**를 찾아 점선 테로 보여 준다(누르면 그 테로 영역을 시작, 아래 경계는 사람이 고침).
- 후보는 도면에 들어가지 않는다. 받아들인(눌러서 확정한) 것만 빗금.
- **완료 조건:** 후보 찾기 함수(`core/`, 영상 배열 입력)의 시험 · 후보 화면 캡처 · 받지 않은 후보가 SVG에 없음을 확인.

### 단계 A3 · 평면 돌 · 기와 · 유물 윤곽(반자동)
- **도구 「윤곽 따기」(키 O)** — 평면에서. 두 가지 도움:
  1. **국소 기복 보기**: 메시 높이 − 반경 r(기본 0.5 m) 평균 높이를 회색조로 겹쳐 보여 줌(보기 켜기 · 끄기). 돌 · 기와가 솟아 보인다.
  2. **후보 윤곽**: 국소 기복이 기준(기본 3 cm) 넘는 곳의 등고선을 점선으로. 누르면 그 윤곽을 시작, 점을 끌어 고친다.
  3. 손으로 따기: 클릭으로 점을 찍고, Shift를 누르면 가장자리(색 · 기복이 바뀌는 곳)에 붙는다.
- 종류: 돌 · 기와 · 유물 · 기타. 모델별로 저장(실좌표 X · Y).
- `core/`: `localRelief(높이 격자, r)` · `contoursAbove(격자, 기준)`(마칭 스퀘어). 시험 먼저: 평평한 면 = 0, 솟은 원기둥 하나 = 원 윤곽 하나, 경사면은 기복 0에 가까움.
- 출력: SVG · DXF 층 `PLAN_OUTLINE_STONE` · `_TILE` · `_ARTIFACT` · `_OTHER`(종류별).
- **완료 조건:** core 시험 통과 · 합성 모델(돌 · 기와 모양을 넣어 만든 시험 모델 — `asec-make-synthetic`에 선택 사항으로 추가)에서 후보 → 확정 → SVG 층 확인.

### 정한 것 (사용자 확정 2026-10-09)
- **평면 윤곽은 SVG · DXF 층만**: 종류별 층으로 넣고(켜고 끌 수 있음) PDF · PNG 평면도에는 넣지 않는다. 「평면도 그림 칸은 정사영상만」 규칙은 PDF · PNG에서 그대로.
- **단면 빗금 기본 = 사선 45° · 종이 위 1.0 mm**(선 0.13 mm). 조판 설정에서 검은 칠 · 점묘로 바꿀 수 있다.

### (아래는 질문 당시의 원문 — 기록)
1. **평면도에 윤곽을 그려도 되는가.** 확정 규칙 「평면도 그림 칸은 정사영상만」과 부딪친다. 추천: **SVG · DXF에는 따로 층으로 넣고(기본 켜짐), PDF · PNG 평면도에는 기본으로 넣지 않는다.** 규칙을 바꿀지는 사용자가 정한다.
2. **단면 빗금 표기 기본값.** 추천: 사선 빗금 45° · 종이 위 1.0 mm. 보고서 규칙에 따라 검은 칠 · 점묘를 고를 수 있게 한다.

### 하지 말 것
- 사람이 확인하지 않은 후보를 도면에 넣기 · 후보를 「확정」으로 저절로 바꾸기
- 묻힌 아래 경계를 메시에서 「추정」해 그리기(메시에 없는 정보)
- 단면선이 바뀌었는데 빗금 영역을 저절로 옮겨 맞추기
